# Issue 対応順序

複数 Issue を並行・順次対応する際の優先順位と依存関係を定義する。

## 依存関係図

```
#9 Branch Protection
#1 Setup
  ├── #10 Hooks（#1完了後）
  └── #3 DB
        ├── #2 Auth（#3完了後）
        │     ├── #4 Receipt Upload（#2完了後）
        │     │     └── #5 Vision（#4完了後）
        │     │           └── #6 Chat（#5完了後）
        │     │                 └── #7 UI（#6完了後）
        │     └── #7 UI（#6完了後）
        └── #8 AWS Infra（#3以降、機能実装と並行可）
```

| Phase 2 | #10 | コード品質チェック用 Hook の設定 | #1 |
| Phase 2 | #3 | データベーススキーマ設計・マイグレーション | #1 |
| Phase 3 | #2 | Google OAuth 認証実装 | #3 |
| Phase 4 | #4 | レシート画像アップロード・S3保存 | #2 |

## 並行作業可能な Issue

- **#9** はいつでも対応可能（コードに依存しない）
- **#8** は Phase 3 以降であれば機能実装と並行して進められる
- **#10** と **#3** は #1 完了後に並行対応可能

## 更新ルール

- Issue が追加・変更された場合はこのファイルを更新する
- 新たな依存関係が判明した場合も即座に反映する
